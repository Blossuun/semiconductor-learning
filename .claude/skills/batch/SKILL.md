대상: $ARGUMENTS
(비어 있으면 다음 미완료 작업 10개. 숫자 하나면 그 개수. `T-번호`들이면 그 작업들.)

## 1. 대상 뽑기
- `Grep`으로 TASKS.md에서 `^\| \[ \] T-\d+` 줄을 위에서부터 필요한 개수만 가져온다. TASKS.md 전체를 읽지 않는다.
- 각 줄의 칸: 번호 / 유형 / 모델 / 작업 / 읽을 파일 / 완료 기준 / 진행.

## 2. 차례 나누기
표에 적힌 순서를 지키면서 "진행" 칸으로 차례를 나눈다.
- `동시`: 바로 이어지는 `동시` 작업끼리 한 차례로 묶어 한꺼번에 맡긴다.
- `단독`: 혼자 한 차례. 앞 차례가 끝난 뒤 시작하고, 끝난 뒤 다음 차례로 간다.
- `직접`: 서브에이전트에 맡기지 않고 본 세션이 직접 한다(브라우저·스킬·아티팩트가 필요한 작업).
- `승인`: 본 세션이 직접 하고, 끝나면 사용자에게 결과를 보여 준 뒤 묶음을 멈춘다. 남은 번호를 알린다.

## 3. 맡기기
- 한 차례의 작업들은 한 메시지에서 `Agent` 호출 여러 개로 동시에 보낸다. `subagent_type`은 `task-worker`.
- 모델 칸이 `S`면 `model: "sonnet"`을 지정하고, `F`면 지정하지 않는다.
- 지시문에는 그 작업 줄의 번호·작업·읽을 파일·완료 기준을 그대로 적는다. 작업이 `/lesson` 또는 `/term`이거나 레슨·용어 작업이면 해당 `SKILL.md`를 먼저 읽으라고 적는다. 디자인 작업이면 `docs/design-system.md`를 따르라고 적는다.
- 작업 줄에 적힌 파일 범위는 사용자가 이미 승인한 것으로 본다. 범위 밖 파일이 필요하다는 보고가 오면 그 작업은 멈춘다.

## 4. 차례가 끝날 때마다
- `완료`로 보고된 작업만 `node .claude/scripts/done.mjs T-번호`로 표시한다.
- `실패`나 `승인 필요`가 있으면 그 뒤 차례를 시작하지 않고 멈춘다. 같은 차례의 다른 작업 결과는 그대로 둔다.

## 5. 마무리 (1회)
1. `node .claude/scripts/merge-terms.mjs`로 용어 조각을 glossary.yaml에 합친다.
2. 용어나 현장 문장이 바뀌었으면 `python scripts/make-audio.py`로 발음 파일을 만든다.
3. `npm run build`를 1회 실행하고 출력 끝부분만 본다. 실패하면 원인 파일을 고치고 다시 1회 실행한다. 그래도 실패하면 오류를 그대로 보고한다.
4. 보고: 작업마다 한 줄(번호, 결과), 남은 번호 한 줄, 사용자가 확인할 방법 한 줄.

커밋은 하지 않는다. 뽑은 대상 밖의 작업을 이어서 시작하지 않는다.

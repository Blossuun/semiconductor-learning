대상: $ARGUMENTS
(비어 있으면 다음 미완료 작업 10개. 숫자 하나면 그 개수. `T-번호`들이면 그 작업들.)

## 1. 대상 뽑기
- `Grep`으로 TASKS.md에서 `^\| \[ \] T-\d+` 줄을 위에서부터 필요한 개수만 가져온다. TASKS.md 전체를 읽지 않는다.
- 각 줄의 칸: 번호 / 유형 / 모델 / 작업 / 읽을 파일 / 완료 기준 / 진행.
- 칸에 "공통"이 있는 작업(예: 9절 실무 심화)은 그 작업이 속한 절의 `공통 ...` 줄들과 `실수 방지 점검` 목록을 Grep(`-A`로 필요한 줄만)으로 1회 가져온다. 절 제목 줄부터 표 머리 줄 전까지가 그 범위다.

## 2. 차례 나누기
표에 적힌 순서를 지키면서 "진행" 칸으로 차례를 나눈다.
- `동시`: 바로 이어지는 `동시` 작업끼리 한 차례로 묶어 한꺼번에 맡긴다.
- `단독`: 혼자 한 차례. 앞 차례가 끝난 뒤 시작하고, 끝난 뒤 다음 차례로 간다.
- `직접`: 서브에이전트에 맡기지 않고 본 세션이 직접 한다(브라우저·스킬·아티팩트가 필요한 작업).
- `승인`: 본 세션이 직접 하고, 끝나면 사용자에게 결과를 보여 준 뒤 묶음을 멈춘다. 남은 번호를 알린다.

## 3. 맡기기
- 한 차례의 작업들은 한 메시지에서 `Agent` 호출 여러 개로 동시에 보낸다. `subagent_type`은 `task-worker`.
- 모델 칸이 `S`면 `model: "sonnet"`을 지정하고, `F`면 지정하지 않는다.
- 지시문에는 그 작업 줄의 번호·작업·읽을 파일·완료 기준을 그대로 적는다. 작업이 `/lesson` 또는 `/term`이거나 레슨·용어 작업이면 해당 `SKILL.md`를 먼저 읽으라고 적는다. 디자인 작업이면 `docs/design-system.md`를 따르라고 적는다.
- 칸에 "공통"이 있는 작업이면 1단계에서 가져온 공통 규칙·공통 읽을 파일·공통 고칠 파일·공통 완료 기준과 점검 A(작업자 몫)를 지시문에 그대로 붙인다. "공통 고칠 파일"이 그 작업의 파일 범위다. 이때는 lesson SKILL을 읽으라고 적지 않는다(새 레슨 작성용이라 기존 레슨 보강과 충돌한다). 점검 B는 본 세션 몫이므로 붙이지 않는다.
- 실무 심화 작업이면 다음도 적는다: "작업에 '검색 필요'가 있으므로 웹 검색을 한다. 수치 대조표 `.claude/tmp/checks/T-번호.md`를 반드시 만든다. 점검 6의 `src/content/lessons/` Grep은 허용한다."
- 읽을 파일이 `glossary.yaml`인 기존 용어 수정 작업이면 "`src/data/glossary.yaml`을 직접 고쳐도 된다"고 적는다. 적지 않으면 작업자는 그 파일을 고치지 못한다.
- 한 차례에 작업이 여러 개면 지시문마다 다른 작업자가 고치는 파일을 적고 건드리지 말라고 한다.
- 지시문 끝에 항상 적는다: "완료 기준을 채우지 못했으면 `완료`가 아니라 `실패`로 보고한다. 직접 대조하거나 확인하지 않은 것을 확인했다고 적지 않는다."
- 검수 작업이면 "출처 내용과 실제로 대조한 항목만 `verified: true`로 바꾸고, 나머지는 그대로 둔 채 id를 보고한다"고 적는다.
- 작업 줄에 적힌 파일 범위는 사용자가 이미 승인한 것으로 본다. 범위 밖 파일이 필요하다는 보고가 오면 그 작업은 멈추고, 필요한 파일 목록을 마무리 보고에 적는다.

## 4. 차례가 끝날 때마다
- 작업자는 빌드와 브라우저를 쓰지 못한다. 보고의 `완료`를 그대로 믿지 않고 본 세션이 완료 기준을 직접 확인한다.
  - 글·데이터 기준(검색 결과 0건, 개수 0개 등): `Grep`으로 센다.
  - 화면 기준: 개발 서버(`preview_start`의 `astro-dev`)에서 본다. 4321 포트에 이미 떠 있으면 그 서버를 쓴다. 주소는 `/semiconductor-learning/`로 시작한다. 휴대폰 기준은 폭 375로 본다.
  - 점검 B가 있는 작업(실무 심화): 그 절의 점검 B 항목을 작업마다 모두 수행한다. 대조표 파일이 없거나, 출처 URL이 2개 미만인 수치가 레슨에 남아 있거나, `node -e` 재계산이 레슨 숫자와 다르거나, `git diff`에 「실무 심화」·퀴즈 추가분 밖의 `-` 줄이 있으면 기준 미달이다. 빌드는 5단계에서 1회 한다.
- 기준을 채운 작업만 `node .claude/scripts/done.mjs T-번호`로 표시한다. 보고가 `완료`여도 기준을 못 채웠으면 표시하지 않는다.
- 기준에 조금 못 미치고 그 작업의 파일 범위 안에서 고칠 수 있으면 본 세션이 직접 고치고 다시 확인한다. 아니면 같은 작업자에게 `SendMessage`로 1회 다시 맡긴다. 그래도 안 되면 `실패`로 둔다.
- `실패`나 `승인 필요`인 작업은 미완료로 두고, 그 작업과 같은 파일을 고치는 뒤 작업만 건너뛴다. 나머지 차례는 계속한다. 같은 차례의 다른 작업 결과는 그대로 둔다.

## 5. 마무리 (1회, 중간에 멈췄어도 실행)
1. `node .claude/scripts/merge-terms.mjs`로 용어 조각을 glossary.yaml에 합친다.
2. 용어나 현장 문장이 바뀌었으면 `python scripts/make-audio.py`로 발음 파일을 만든다.
3. `npm run build`를 1회 실행하고 출력 끝부분만 본다. 실패하면 원인 파일을 고치고 다시 1회 실행한다. 그래도 실패하면 오류를 그대로 보고한다.
4. 보고: 작업마다 한 줄(번호, 결과, 확인한 방법), 미완료 작업마다 이유와 필요한 승인 한 줄, 남은 번호 한 줄, 사용자가 확인할 방법 한 줄.

커밋은 하지 않는다. 뽑은 대상 밖의 작업을 이어서 시작하지 않는다.
